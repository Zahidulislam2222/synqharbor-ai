# Accessibility

Last reviewed: 2026-10-16.

The design targets WCAG 2.2 AA and includes reduced motion, keyboard operation and responsive layouts. Full conformance requires continued human and automated evaluation.

## Built into the interface

Semantic navigation, visible focus, labeled controls and motion preferences support everyday use.

- Reduced-motion media behavior
- Responsive reflow and readable contrast
- Dialogs and mobile navigation focus handling

## Verification approach

Automated checks cover selected routes and interaction states. Keyboard, zoom, assistive technology and real-device checks extend that evidence.

- Test complete workflows rather than isolated widgets
- Inspect validation and status announcements
- Record and fix barriers found after release

## Report a barrier

Use the contact page with the affected URL, browser, assistive technology and a description of the issue. Include only information you are comfortable sharing.

- Alternative formats can be discussed
- Public issues for non-sensitive barriers
- No accessibility certification is asserted

Contact: [project maintainer](https://github.com/Zahidulislam2222). Arrange a private channel before sharing personal data; never put credentials or confidential data into public issues.
